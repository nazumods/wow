# ShadowsOfUI-Castbar

**Deps:** LibNAddOn, LibNUI · **SavedVars:** `ShadowsOfUI_CastbarDB` (v2) · **UI:** LibNUI · **Settings:** subcategory under the shared "Shadows of UI" parent · **Slash:** `/scast`

Two movable, cosmetic cast bars — one for the **target** unit, one for the **focus** unit —
in the suite's minimal style (siblings to `ShadowsOfUI-XP` / `ShadowsOfUI-GCD`). Built on
LibNUI's `StatusBar`. Reads `UnitCastingInfo` / `UnitChannelInfo` only (no secret/stat APIs),
so it's purely cosmetic and combat-safe (insecure frames, no `SetAttribute`).

## Files

| File | Purpose |
|---|---|
| `core.lua` | Bootstrap (assignment form). `MigrateDB` seeds `textSize` + per-bar `*Enabled` flags + `*Pos` tables. `ns:RegisterSettings` (two enable checkboxes + an 8–22px text-size slider) nested under the **Shadows of UI** parent. `onLoad` builds `ns.bars` (`target` + `focus` `CastBar`s) and calls `ns:WireEditMode` + `ns:WireSettingsPreview`. `ns:SetBarEnabled`/`ns:ApplyTextSize` apply settings live. `ns:WireSettingsPreview` `hooksecurefunc`s `SettingsPanel:DisplayCategory` + the `SettingsPanel.OnHide` `EventRegistry` callback → `ns:SetPreview(category == ns.settingsCategory)`, so both bars show static samples while *our* panel is open and the text-size slider's effect is visible live. `SLASH_SUI_CASTBAR1 = "/scast"` (base opens settings, `dump` prints state). |
| `CastBar.lua` | `ns.CastBar` — a `StatusBar` subclass per unit. Icon (inset top-left) + spell-name `Label` + remaining-time `Label` + darkened top edge. Registers the `UNIT_SPELLCAST_*` events **per-unit** via `RegisterUnitEvent` (so "target"/"focus" follow the live unit) plus the `PLAYER_TARGET_CHANGED`/`PLAYER_FOCUS_CHANGED` change event (passed as the `events` option); every one just calls `Refresh`. `Refresh` re-reads `UnitCastingInfo`→`UnitChannelInfo`, paints, and shows. The fill is the **native `StatusBar`** (`SetMinMaxValues(startMS, endMS)` + per-frame `SetValue(GetTime()*1000)`) so the engine computes it in C — Lua never does arithmetic on the **secret** cast times (see gotcha); hiding is driven by the `*_STOP` events, not a Lua compare against the secret end time. `onUpdate` only computes the time text when the timing is readable. A static placeholder **sample** (`_syncSample`) is shown whenever Edit Mode (`SetConfig`/`_editMode`, draggable) or the settings panel (`SetPreview`/`_preview`, look-only) is active **and the bar is enabled** (a disabled bar stays hidden everywhere); `Refresh` bails while a sample is active, and `enableDrag` is armed for Edit Mode only. `SetEnabled` routes through `_syncSample` (not just `Refresh`) so toggling the checkbox while the panel is open shows/hides the preview immediately. **Edit Mode placement**: `enableDrag` (armed for Edit Mode only) shows/tints the selection box (`_sel`, built + styled by methods in `editmode.lua`), wires `OnEnter`/`OnLeave` to brighten it on hover, left-drag to move (writes the dragged TOPLEFT offset into the DB `pos`), and `OnMouseUp` → **left-click (no drag) opens the config popup** (`ns:OpenConfig`) — a drag sets `_didDrag` so the trailing click is ignored. `SetEnabled`/`SetTextSize` back the settings. |
| `config.lua` | The per-bar **config popup** — our stand-in for Blizzard's `EditModeSystemSettingsDialog`. `ns:_buildConfig` lazily builds one shared `ui.TitleFrame` (DIALOG strata) with: an enable `CheckButton` (writes `db.<unit>Enabled` + `ns:SetBarEnabled`), the shared text-size `Slider` (writes `db.textSize` + `ns:ApplyTextSize`; setting `Value` from `OpenConfig` fires `OnChange` with `userInput=false` to sync the px label without re-writing the DB), and a "Reset position" `Frame`-button (`bar:ResetPosition(ns.DEFAULT_POS[unit])`). `ns:OpenConfig(bar)` points the popup at the clicked bar (title + control values), marks it selected (`SetSelected`), and `ns:AttachConfig` anchors the popup `TOPLEFT→bar BOTTOMLEFT` so it follows the bar live while dragged. `ns:CloseConfig` hides it + clears selection. |
| `editmode.lua` | `ns:WireEditMode` `hooksecurefunc`s `EditModeManagerFrame:EnterEditMode`/`ExitEditMode` → `ns:SetConfigMode(on)`, which flips every bar's `SetConfig` and, on exit, calls `ns:CloseConfig` to dismiss the popup. Guarded so a missing/renamed mixin just leaves the bars in live mode. Also **re-opens the `CastBar` class** (`local CastBar = ns.CastBar`) to add the selection-box methods — `_buildSelection` (four cyan border strips `_sel`; called once from the constructor), `_selectStyle` (`SEL_DIM` idle / `SEL_HOT` hot), `SetSelected`/`_selected` (marks the bar whose popup is open), and `ResetPosition` — keeping all Edit-Mode visual code in one file. |

## Gotchas

- **`core.lua` loads first** (it's the `LibNAddOn(...)` setup file, so `ns.ui`/`ns.Colors` exist for the other files); `ns.CastBar` / `ns:WireEditMode` are only *used* in `onLoad`, which runs long after all files load.
- **Edit Mode is not a real registration.** WoW has no public Edit Mode API for third-party frames, so the bars piggy-back on the manager's enter/exit hooks to show a draggable sample. This is the intended approach (see issue #263), not a true Edit Mode "system". The **selection box** (`CastBar._sel` border strips) and the **click-to-configure popup** (`config.lua`) are likewise hand-rolled stand-ins for Blizzard's `Selection` frame + `EditModeSystemSettingsDialog`, not the real ones — replicating the look/feel (highlight on hover, brighten + popup on click) with LibNUI widgets rather than registering into the inaccessible system.
- **Click vs drag.** The sample arms both an `OnMouseUp` (open popup) and `RegisterForDrag("LeftButton")` (move). A real drag sets `_didDrag` in `OnDragStart`, which the trailing `OnMouseUp` checks and clears so a drag never also opens the popup. `OnDragStart` always fires before button release, so this is order-independent of `OnDragStop`.
- **Popup follows the bar.** `AttachConfig` anchors the popup `TOPLEFT → bar BOTTOMLEFT`, so dragging the bar moves the popup live (no per-frame re-anchor needed). Dragging the popup itself (TitleFrame `drag`) re-anchors it to UIParent until the next `OpenConfig`/`AttachConfig`.
- **Position is a live DB reference, anchored top-left.** Each bar's `pos` is the actual `db.targetPos`/`db.focusPos` table, so a drag mutates the DB directly; `applyPosition` anchors the bar's **`TOPLEFT → UIParent CENTER`** with the saved offset — top-left (not centre) so `_applySize` growing the bar for a larger font extends it down/right from a locked corner. Offsets assume the bar and `UIParent` share an effective scale (both parent to `UIParent`). **DB v2** switched this from centre-anchored; `MigrateDB` converts a pre-v2 centre offset to the matching top-left offset via `ns.CastBar.dims(textSize)`, preserving placement.
- **Bar scales with text size.** `dims(textSize)` → `height = textSize + V_PAD (10)`, `width = height × W_PER_H (10)`; `_applySize` (construction + every `SetTextSize`) sizes the bar + icon. Default 12px → 220×22, 22px → 320×32. Exposed as `ns.CastBar.dims` for the v2 migration.
- **Per-unit events, not global.** `RegisterUnitEvent(event, "target"|"focus")` means each bar only wakes for its own unit; on a target/focus change the change-event handler re-`Refresh`es to catch an already-in-progress cast.
- **Secret cast values (anti-automation).** An enemy target/focus's `UnitCastingInfo` timing (`startMS`/`endMS`) and `notInterruptible` flag are **secret** values — tainted addon code may *pass* them to C but not do arithmetic/boolean tests on them (else `attempt to … a secret … value, while execution tainted`). So the fill is driven by handing the secret times to the native `StatusBar` (C does the math), the interrupt colour is only applied when `canaccessvalue(notInterruptible)`, and the **time text only shows when `canaccessvalue(endMS)`** (i.e. your own / friendly casts; blank for enemies). Name/icon/texture are *not* secret. This hinges on the engine accepting secret values *through* `SetMinMaxValues`/`SetValue` (a "pass, don't inspect" use) — **pending in-game confirmation**; if it rejects them, the fallback is to reskin Blizzard's own (secure) target/focus cast bars. See [[reference_wow_secret_values]].
- **Settings variable keys must be unique.** The two enable checkboxes use distinct DB keys (`targetEnabled` / `focusEnabled`) because `ns.registerSettings` derives the (addon-global) Settings variable id from the key — a shared `enabled` key would collide.
- **Font size via a borrowed path.** `FONT_PATH = GameFontHighlightSmall:GetFont()` — the name/time `Label`s use `{FONT_PATH, size}` so the slider can resize them at runtime without shipping a font.

## SavedVariables (`ShadowsOfUI_CastbarDB`)

```lua
{
  version       = 2,
  textSize      = 12,                    -- spell-name / time font size, 8–22
  targetEnabled = true,                  -- show the target bar for real casts
  focusEnabled  = true,                  -- show the focus bar for real casts
  targetPos     = { x = -110, y = 171 }, -- bar TOPLEFT offset from UIParent's centre
  focusPos      = { x = -110, y = 135 },
}
```
`MigrateDB` seeds missing keys, and at **v2** converts a pre-v2 centre-anchored `*Pos` to the top-left-anchored equivalent (using the bar size at the current text size) so the dragged placement carries over.
