# Warbandeer_Collected

**Deps:** LibNAddOn, LibNUI, LibNUI-ModelViewer, Warbandeer_Characters · **SavedVars:** `WarbandeerCollectedDB` (v4) · **Commands:** `/collected`, `/collect` (no-arg opens the window; `scan`; `wanted` lists wanted sets; `model <id>` / `scale <n>` / `normalize <0..1>` / `release <1..12>` / `coverage [all]` / `weapons [<category>]` dev verify) · **Reads:** `WarbandeerApi` · **UI:** LibNUI · **Compartment:** `WarbandeerCollected_OnAddonCompartmentClick` · **Exposes:** `WarbandeerCollectedApi` (data bridge for Warbandeer's `collected` view — reads scan data, reads + **writes** the wanted/rank ratings)

Transmog set collection tracker. Renders a class × instance-set grid showing, per character, how many appearances of each tier/dungeon set remain uncollected, plus per-character instance lockouts. Each class set also carries two account-wide, user-authored **ratings**: a **wanted** flag (your target list) and an **S–F tier rank** (a global baseline with optional per-race overrides) — see [Ratings](#ratings).

## Data Model (`ns.Sets`)

```lua
{ id, name, release, instance, difficulty, minLevel?,
  sets = { { id, name, classId }, ... } }  -- one entry per class set; id is the base set id
```
`release` indexes `ns.Releases`; `instance`/`difficulty` key into a character's `instances.locks` (from the data layer) for lockout display. Set blocks are regenerated from wago.tools — see `tools/UPDATING.md`.

## SavedVariables (`WarbandeerCollectedDB`)

```lua
{ version = 4, collected = int, total = int,
  sets    = { [groupId] = { [setId] = true | { collected, parts, total } } },  -- scan output
  wanted  = { [setId] = true },                  -- target list
  rank    = { [setId] = "S".."F" },              -- baseline tier
  raceRank = { [setId] = { [raceId] = "S".."F" } },  -- per-race overrides
  dressPos = { point, relPoint, x, y },          -- set-preview window position
  windowPos = { point, relPoint, x, y } }        -- main window position
```
- `true` = base set fully collected; otherwise a partial record (`parts` is the raw `GetSetPrimaryAppearances` array).
- The three rating tables are keyed by the **globally-unique base `setId`** (not nested under `groupId` like `sets`), so they're group-independent and survive a re-scan (`/collected scan` wipes only `sets`/`collected`/`total`). `raceId` is the canonical race id (`ns:PlayerRace()` / the dressing-room selector).
- `MigrateDB` is non-destructive: only ensures missing top-level keys exist (v3 adds `wanted`/`rank`/`raceRank`; v4 adds `dressPos`/`windowPos`).

### Remembered window positions

`dressPos` (set-preview / dressing room) and `windowPos` (main window) hold each window's last dragged anchor as `{ point, relPoint, x, y }` (relative to `UIParent`). They're populated by `TitleFrame:RememberPosition(store)` (LibNUI), called once when each window is lazily built (`ns.ShowDressingRoom` / `ns:Open`): the helper restores the saved point right away and re-saves it on every drag-stop, so the windows no longer re-center after a `/reload` or relog (issue #179). Both tables start empty `{}` — an empty store leaves the window at its constructor default (centered).

## Scan Logic (`/collected scan`)

Resets the three DB keys, then for each group → each set with an `id`:
- `C_TransmogSets.IsBaseSetCollected(id)` true → store `true`, bump `collected`.
- else → `GetSetPrimaryAppearances(id)`, count `p.collected`, store `{ collected, parts, total }`.

`total` accumulates `#grp.sets`. After scanning, refreshes `ns.window.counter` and `ns.window.data`. The rating keys (`wanted`/`rank`/`raceRank`) are **not** touched.

The scan body is the reusable `ns:Scan()` method (in `commands.lua`, silent); the `scan` command calls it then prints, the compartment right-click calls it, and a **`TRANSMOG_COLLECTION_UPDATED`** handler calls it (debounced via `self:delay(500, …)`, skipped until the first manual scan) so the counts/grid update live when you learn an appearance. After refreshing its own window, `ns:Scan()` fires the **`API:OnScanned`** subscribers (`ns._scanned`) — Warbandeer's collected view registers one to re-render in sync, reading the now-fresh DB with no debounce race.

## Ratings

Two account-wide, user-authored attributes per class set, independent of each other and of collection status:

- **Wanted** — a boolean target list. Toggle by Shift-clicking a grid cell (`/collected` window or Warbandeer's `collected` view) or the dressing room's **Wanted** button. Surfaced as a gold star on the cell, an `★ N` window counter, the InfoTip status line, the `/collected wanted` chat list, and a **Wanted only** grid filter that shows only rows holding a wanted set (non-wanted class cells within a shown row still blank; when nothing is flagged, a centered "You don't have any Wanted sets." message via `DataView:_setEmpty`).
- **Rank** — an `S/A/B/C/F` aesthetic tier. A single **baseline** per set plus optional **per-race overrides** (the same look reads differently on different races). Edited only in the dressing room (it has the race selector): the tier buttons write the baseline, or the override for the selected race when **This race** is active. `ns:EffectiveRank(setId, raceId)` resolves override → baseline → nil; grids render the effective rank **for the logged-in character's race** as the tier letter in its tier color (top-right of the cell), and the InfoTip shows it too (`(race)` when an override applies).

Model + accessors live in `ratings.lua` (on `ns`); `api.lua` forwards them to consumers since the DB is account-wide. The shared dressing room and the `DataView` grid (rendered both in Collected's own window and embedded in Warbandeer's `CollectedView`) all read/write the same data.

## Gotchas

- **Grid cells show *uncollected* count, not collected** — `text = total - collected`, and the gradient shade is keyed by the *collected* fraction (`floor(collected/total*10)`), so a low number on a green cell means nearly done.
- **InfoTip slot order is fixed** — it walks slots `{1,3,15,5,6,7,8,9,10}` (Head, Shoulder, Back, Chest, Waist, Legs, Feet, Wrist, Hands — the `rowInfo`/`data` rows stay parallel to this list), matching `GetSourcesForSlot` against the set's primary `appearanceID`s; collected sources green, missing red. Back (cloak, slot 15) must be in this list or sets with a cloak silently drop it.
- **Trading Post / variant sets serve no per-slot sources.** `C_TransmogSets.GetSourcesForSlot(setID, slot)` returns empty for *every* slot on some sets (e.g. the Trading Post recolors, group `id` 47's `(Trading Post)` entry) even though `GetAllSourceIDs(setID)` still has all the pieces and the model wears them. Both the dressing-room slots and the InfoTip fall back to `ns.SetSlotPieces(setID)` (in `DressingRoomSlots.lua`), which buckets `GetAllSourceIDs` into slots by each piece's `GetItemInfoInstant` equip location.
- **Lockout state lives in the data layer**, not here — read via `api.GetAllCharacters()` → `toon.instances.locks[group.instance][group.difficulty]`.
- **`ns:CompartmentClick`**: right-click runs the scan, any other click opens the window.
- **DataView auto-sizes the name column** at construction from the widest row label, then grows `rowArea`/self to match.
- **Rating overlays refresh after the table rebuilds, not during it.** `DataView` overrides `update()` to call `TableFrame.update(self)` then `_refreshMarks()`. But the constructor-time `update()` (from `TableFrame:onLoad`) runs *before* the subclass's `update` is mixed onto the instance (see the `Class` Mixin order), so it'd skip marks — hence the constructor calls `self:_refreshMarks()` once explicitly at the end. Cells persist across re-sorts, so their `_wantStar`/`_rankPip` children persist too and are just shown/hidden.
- **Marks read live DB, cells carry only the `setId`.** A wanted/rank change only needs a `_refreshMarks()` (or a single `_applyCellMarks(cell, setId)` for the toggled cell) — no `GetData()` rebuild — *unless* the wanted-only filter is active, where the toggled set must appear/disappear, so those paths rebuild.
- **Arbitrary races need a `ModelScene` actor, not a bare `DressUpModel`.** `SetCustomRace` was removed, and `DressUpModel:SetDisplayInfo` renders non-player races untextured (white). The `ui.Model` widget borrows dressup scene 596 and skins its actor via `SetModelByCreatureDisplayID` (exact race+gender, needs a display ID) or `SetModelByUnit("player", …, customRaceID)` (any race, textured, gender = the char's). `ns.RaceModels` only supplies the former; it is hand-maintained and unverified beyond the Allied Races ids — verify in-game.
- **InfoTip show/hide is immediate.** Cell `onEnter` re-anchors and renders right away; `onLeave` hides at once. (An earlier version debounced reposition and deferred the hide so a **Preview** button inside the tip stayed clickable — both removed; the dressing room now opens only from the grid cell's `onClick`.)
- **Weapon-cosmetic groups are a parallel API surface (#516).** The `data/weapons.lua` groups are `kind`-tagged (`illusion`/`arsenal`) and scanned via `ns:_scanWeaponSet` off `C_TransmogCollection` (`GetIllusionInfo(sid).isCollected` / `PlayerHasTransmog(itemID)`), writing `db.sets` in the same `true`/`{collected,total}` shape so the grid, filters, wanted/rank, counts, and `/collected wanted` all work unchanged (no `CollectedRows` edit). `ShowInfoTip`/`ShowDressingRoom` branch on `group.kind`: hover shows a native summary tooltip (`weaponTip` in `InfoTip.lua`, cursor-anchored — the fixed 9-slot armor table can't hold an illusion list or a 15-weapon bundle); left-click opens the dressing-room **weapon preview** (`_dressWeapon` in `DressingRoomModel.lua`: renders the char's own race — decision B — holding the arsenal weapon appearance, or a host weapon + enchant illusion via `Model:SlotTransmog`; `_showSlots(false)` + hidden tier bars strip the armor chrome; the up/down nav cycles pieces via `_stepWeaponPiece`; `_titleWeapon` surfaces the piece's real name in the title, retitling async for arsenal item names; host weapon = `ns.HostWeaponAppearance()`, the char's equipped main-hand). Illusion owned-state via `GetIllusionInfo(sourceID).isCollected` with **hardcoded sourceIDs** (Razorice 5869, Poisoned 5364, Shaman brands 5871–5875) — **account-wide + cross-class**: `GetIllusions()` only enumerates the current char's *usable* illusions, so a name-match against it can't see other-class ones, whereas `GetIllusionInfo(sid)` returns a valid account-wide `isCollected` on any character. **Follow-ups (NOT #516):** obtain-source hints for unowned pieces — DONE (#598): `weaponTip` appends a **How to obtain** line for an incomplete set from a curated inline `obtain=` field on the illusion/arsenal set — NOT the illusion API `sourceText`, which dedupes by visual and traces each shimmer to the oldest item bearing it (Flametongue → Ragnaros), so it misleads. Matches the glyph/green-fire pattern (see [[project_wow_glyph_sources]]); the general **weapon+illusion look builder** is its own epic (**#596**), where the class illusions/arsenals become picker entries; a themed weapon InfoTip. The **all-weapon-illusions** collection (Mongoose etc.) is deliberately out of scope — those are class-agnostic + account-wide, so they don't fit the class grid (#596 territory).
