# Tooling

Reusable development tooling for the suite. **Not an addon** — nothing here is
shipped, listed in a `.toc`, or picked up by the release pipeline (`release.sh`
skips folders without a `.toc`, and `Tooling` is on its `NON_ADDON_DIRS` list).

Check this directory **before writing a new one-off script** — the job may
already be solved here. When a scratchpad script proves reusable, promote it
into this directory with a docstring and an entry in the table below.

| Script | Purpose |
|---|---|
| `make_addon_logo.py` | **Warbandeer-family logo generator** (stag crest style). Reuses the crest base in `assets/` (`warbandeer_base.png`): erases the ribbon's "ADDON NAME" placeholder and resets it with the given text (Arial Bold, tan ink `rgb(191,176,138)` on the ribbon's purple `rgb(81,63,81)`), condensed to fit between the ribbon's fixed flanking arrows. Only the ribbon suffix varies — the "WARBANDEER" title is baked into the base and never changes. `python Tooling/make_addon_logo.py Characters --out <addon>/logo.png` |
| `make_moon_logo.py` | **ShadowsOfUI-family logo generator** (purple moon style). Reuses the moon-art base in `assets/`: inpaints out its word and re-sets the given text in the measured typography (Times New Roman, 94.4% condense, cream ink, cap height ≤79px shrinking to a 235px max width). 400×400 output. `python Tooling/make_moon_logo.py Castbar --out <addon>/logo.png` |
| `make_summary_icon.py` | **Warbandeer Summary-column icon generator.** Turns a game icon into the 64×64 32-bit white-silhouette TGA (muted-tinted at runtime) that every `Warbandeer/views/summaryCol/*.lua` header uses. Fetches the real art from the Wowhead icon CDN by name (`--icon-name inv_…`) or converts a local PNG/JPG (`--src`); alpha from source luminance, RGB forced white, house-format header written byte-for-byte. Pipeline for a new currency column: Wowhead `currency=<ID>` → Warcraft Wiki reports the icon name → run the tool → add the column `.lua` + `.toc` entry. `python Tooling/make_summary_icon.py --icon-name inv_10_gathering_bioluminescentspores_large --out Warbandeer/icons/unalloyedabundance.tga` |
| `make_vault_assets.py` | **Warbandeer Great Vault view assets.** Generates the three 64×64 house-format TGAs the `/wb vault` view needs: `icons/pip-full.tga` (gold filled disc = unlocked slot) and `icons/pip-empty.tga` (muted ring = locked slot), both rendered inline in a table cell via `\|T…\|t` markup, plus `icons/views/vault.tga` (a white vault-door rail glyph, tinted at runtime by `IconStrip` like the other view glyphs). Pip colours are baked in (inline markup can't carry a vertex colour); the glyph is drawn procedurally, so no network / icon-name lookup. `python Tooling/make_vault_assets.py [--preview out/]` |
| `make_endeavor_assets.py` | **Warbandeer Endeavors-column assets.** Generates the Summary `Endeavors` column's art (issue #550): four 64×64 baked-colour crest TGAs rendered inline via `\|T…\|t` markup — `icons/endeavor-{alliance,horde}.tga` (faction-coloured crests, used in the Overview house blocks) and `icons/endeavor-{alliance,horde}-sub.tga` (crest + gold border box = the endeavor a character is *actively feeding*, shown in the column cell) — plus `icons/endeavors.tga`, the column's white carpenter's-hammer header glyph (muted-tinted at runtime like the sibling headers). Crest colours are baked in (inline markup can't runtime-tint; the ringed variant needs two colours). Reuses the existing white crest silhouettes (`icons/{alliance,horde}.tga`). `python Tooling/make_endeavor_assets.py [--preview out/]` |
| `make_weapon_type_icons.py` | **Warbandeer_Collected Weapons-grid column icons.** Generates the 17 house-style white-silhouette TGAs (`Warbandeer_Collected/textures/weapons/*.tga`, one per `Enum.TransmogCollectionType`) the Weapons grid renders as column headers via `\|T…\|t`, replacing the placeholder text abbreviations. Reuses `make_summary_icon.py`'s CDN-fetch → white-silhouette → house-TGA pipeline and carries the type → icon-name → basename map so all 17 regenerate with one command; `ns.WeaponTypeIcon` (in `WeaponViewData.lua`) keys the same basenames. Rendered untinted (inline `\|T…\|t` can't vertex-tint), so the silhouettes read white on the dark header. `python Tooling/make_weapon_type_icons.py [--only <basename>] [--preview <dir>]` |
| `lint-stale-ids.ps1` | **Suite-wide stale-id lint** (PowerShell). Validates hand-authored WoW id literals in the static data files against the live client DB2 (wago.tools), so a stale/fat-fingered id is caught in CI, not by a user hitting a blank row. Rule-driven: each rule = a data file + an id-extractor regex + the DB2 `table.column` the ids must resolve against; adding a file is adding a rule. Fetches each table once per run (small tables via `ConvertFrom-Csv`, six-figure tables via a raw first-column hash), and with `-CacheDir` persists each table's CSV so the CI workflows' build-keyed `actions/cache` hits wago's heavy endpoints ~once per client build, not per run. Current rules cover `races.lua` (→`ChrRaces.ID`), `professioninfo.lua` skill-line + variant ids (→`SkillLine.ID`), `classmounts.lua` itemIDs (→`Item.ID`, `fail`) + summon spellIDs (→`Mount.SourceSpellID`, `warn` — an incomplete mirror of `GetMountFromSpell`), and `Warbandeer_Collected/weapons.lua` illusion sourceIDs (→`TransmogIllusion.SpellItemEnchantmentID`, not `.ID`) + arsenal/pieces itemIDs (→`Item.ID`) — the latter folded in from the former standalone `verify-weapons.ps1`. A rule whose ids don't fit a single-capture regex supplies an `extract` scriptblock instead (see `weapons.arsenalItemID`). Also covers the larger `Warbandeer_Characters` catalogs — `collectiblesources.lua`, `learnedunlocks.lua`, `glyphinfo.lua` — resolving itemID/startItem→`Item.ID`, spell→`SpellName.ID`, quest/startQuest→`QuestV2.ID`, glyph→`GlyphProperties.ID`. Also gates `achievementcatalog.lua` (→`Achievement.ID`) — the ids the desktop app's static-data bundle is filtered to, so a stale entry surfaces here as a named diagnostic instead of aborting `update-static-data.ps1`; its extractor parses from the `ns.AchievementCatalog` assignment onward, since the `select(2, ...)` import above it would otherwise lint as achievement id 2. `challengetames.lua` is intentionally excluded — its old-content creatureIDs are trimmed out of the client `Creature.db2`, so no client-side source can validate them. `pwsh Tooling/lint-stale-ids.ps1 [-SkipBig] [-Build <ver>] [-CacheDir <dir>]` — exit 1 on any stale fail-rule id; all wago requests send an identifying User-Agent. |
| `update-static-data.ps1` | **Offline lookup-bundle generator** (PowerShell). Builds `apps/warbandeer-desktop/src-tauri/data/static-data.json` from live wago.tools, so consumers can render names/icons that SavedVariables only store ids for. Two tables, admitted on the rule "**what the addon doesn't already persist**": `CurrencyTypes` in full (the one lookup with **no Blizzard REST equivalent** — the Game Data API has no currency endpoint), and `Achievement` filtered to the ~93 ids `Warbandeer_Characters/data/achievementcatalog.lua` declares (`data/achievements.lua` persists only completion bits, and the full table is 13.8k rows / 2 MB). Pins a real product build via `/api/builds`, asserts each table's DB2 columns exist and aborts on a rename rather than emitting nulls, aborts on a tracked achievement id DB2 doesn't know (a stale catalog entry), and resolves icon FileDataIDs → a renderable icon **name** through the `/api/files` listfile (there is no per-FileDataID lookup, so the ~2 MB `interface/icons/` slice is fetched once — hence `-CacheDir`). Guards: per-table row floors, listfile floor, >5% deletion in *either* table, and >5% of *real* currency icon ids missing the listfile (tracked apart from the ~916 rows that legitimately carry no icon). Output records its source build and **no timestamp**, and is LF-normalised, so an unchanged build regenerates byte-identically and the weekly refresh only opens a PR when the data moved. Lives here rather than beside its output because `wow-companion` also consumes it (via the published release) and because anything under `apps/warbandeer-desktop/` triggers `app-release.yml`. `pwsh Tooling/update-static-data.ps1 [-Check] [-CacheDir <dir>] [-Build <ver>]` — see `UPDATING-static-data.md`. |
| `UPDATING-static-data.md` | Companion doc for `update-static-data.ps1`: regeneration workflow, guard rationale, **what earns a place in the bundle** (the settled #639 offline-vs-Blizzard-credentials decision), determinism contract, refresh cadence, and the release-asset contract external consumers (`wow-companion`) depend on. |
| `assets/` | Stable base images the generators derive from: `warbandeer_base.png` (stag crest, current Warbandeer-family base) and `shadowsofui_moon_base.png` (= `ShadowsOfUI-Known/logo.png`). Snapshots so the tools keep working identically even if an addon's own logo changes. `warbandeer_flag_base.png` (green photo flag) is the superseded pre-crest base — kept for reference, no longer used by `make_addon_logo.py`. Also `endeavors_reference.png` — a Midnight housing tile kept as a design reference for the Endeavors column header (not a generator input). |
| `procedural_flag_logo.py` | Superseded reference: draws the whole flag scene procedurally in PIL (no photo base). Kept for the sampled palette/geometry constants. |

## Logo generation notes

- Two house styles, one generator each: **Warbandeer family** = stag crest
  with a purple ribbon (`make_addon_logo.py`), **ShadowsOfUI family** = purple
  crescent moon + cherry blossoms (`make_moon_logo.py`). Match the family to
  the addon prefix.
- The moon base (`ShadowsOfUI-Known/logo.png`) and XP's logo are 400×400
  CurseForge re-encodes (#347); the 1254×1254 originals live with nazumods.

- `make_addon_logo.py` requires only `pillow` and the Windows font
  **Arial Bold** (`C:/Windows/Fonts/arialbd.ttf`) — it falls back to the
  Arial Bold shipped with macOS when run there. `make_moon_logo.py` also
  needs `numpy`, `opencv-python-headless`, and Times New Roman.
- Output is a 1024×1024 PNG, same as the sibling logos
  (`Warbandeer*/logo.png`), upscaled from the 400×400 crest base.
- The run is deterministic: same text + same library versions → byte-identical
  output.
- The crest's ribbon-text style constants were **measured from the base
  art's own "ADDON NAME" placeholder** (tan ink `rgb(191,176,138)` on ribbon
  purple `rgb(81,63,81)`, 34px target cap-height, erase zone clear of the
  ribbon's fixed flanking arrows) — don't tweak them ad hoc or the family
  stops matching. The "WARBANDEER" title is baked into the base and is never
  regenerated; only the ribbon suffix varies per addon (main `Warbandeer`
  addon uses "Core").
