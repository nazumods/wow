# LibNUI ModelViewer

**Deps:** LibNAddOn, LibNUI · **Global:** registers `ui.Model` (`LibNUI.Model`) on the shared LibNUI widget table · **Commands:** none · **DB:** none

Single-widget companion addon: the `ModelScene`-backed 3D model viewer, extracted from core LibNUI (issue #591) so only addons that present a 3D character / transmog viewer carry it. `Model.lua` is the setup file (`local ns = LibNAddOn(...)`); the addon declares `## X-NUI-UI: LibNUI` so `ns.ui` resolves to the shared LibNUI table, then registers `Model` back onto it. Consumers reach it as `ui.Model` / `LibNUI.Model` exactly as before, provided they add `LibNUI-ModelViewer` to their `## Dependencies` so the widget exists at file-load time.

## Files

| File | Purpose |
|---|---|
| `Model.lua` | Setup file (`LibNAddOn(...)`, binds `ns.ui` = LibNUI via `X-NUI-UI`) + the `Model` widget. `ModelScene`-backed 3D viewer (borrows dressup scene 596 for camera + a skinnable player actor); `DisplayInfo(id, useCustomizations?)`/`Unit(token, customRaceID?, useNativeForm?)`/`TryOn`/`Undress`/`UndressSlot`/`Dress`/`Outfit`/`SlotTransmog`/`ClearSlotTransmog`/`Aggressiveness`/`Scale`/`Spin`. `Unit`'s `useNativeForm` (default true) toggles the unit's native vs altered form (Worgen human, Dracthyr visage) — only effective when the unit itself has one. `DisplayInfo` defaults customizations **off** (a baked display carries its own textures; on only matches the player's own race). One player-sized actor renders every model, so races at natural size are inconsistent: `Aggressiveness(n)` (0 = natural, **default**; 1 = forced to ~human-male) drives Blizzard's bounding-box normalization (`SetNormalizedScaleAggressiveness` + `SetRequestedScale`, `effectiveScale = requestedScale * 1/maxBoundingBoxScale` via `UpdateScale`); `Scale(n)` is the user multiplier on top (= `requestedScale`). **Left-drag = actor yaw (rotate, with release inertia), right-drag = camera pan, wheel = camera zoom.** Yaw lives on the actor (so re-skins keep the framing); pan/zoom live on the borrowed scene's `OrbitCamera` (`GetActiveCamera()`): leftX mode set to `NOTHING`, rightX/rightY = `PAN_HORIZONTAL`/`PAN_VERTICAL`, wheel = `ZOOM`, and min/max zoom widened from the scene's tight 6–10 to `minZoom`/`maxZoom` (2/16) so the wheel has travel. Our `OnUpdate`/`OnMouse*` `SetScript`s replace the template's, so they forward to the mixin (`w:OnMouseDown/Up/Wheel`, `w:OnUpdate(elapsed)`) to keep the camera stepping (pan + zoom are eased by the `OrbitCamera`'s own `DeltaLerp` interpolation, default amount `.15`); only `LeftButton` arms the actor-yaw drag. **Rotation inertia:** since the yaw is on the actor (not routed through the eased camera), the drag tracks a throw speed (`_yawVel`, rad/sec, `DeltaLerp`-smoothed by `spinTracking` so placing the model precisely doesn't fling it) and, on release, keeps rotating and glides to a stop via the same engine `DeltaLerp` decay (`spinFriction`, ~1s) down to a `SPIN_CUTOFF` snap; a fresh grab zeroes the velocity. `Spin(v)` reads/sets the live velocity for a programmatic showcase spin (or `Spin(0)` to halt). `ResetView()` restores the load defaults — yaw back to `facing` (zeroing any spin), the captured `_naturalZoom` distance, and pan offsets (`_cam.panningXOffset/panningYOffset`) to 0; the user `Scale` multiplier is left untouched. The dragged yaw and remembered `Outfit` (a sourceID list, empty = undressed) are re-applied via a `SetOnModelLoadedCallback` after each async model load (which would otherwise reset the actor to its baked default), so the angle and worn transmog never snap back. Scale (`_applyScale`) is instead **re-asserted every frame** in `OnUpdate` — a cold first load resets the actor scale *after* the load-callback/backstop fire, so polling is the only reliable way to keep the size correction (idempotent, corrects within a frame). Use `Outfit` rather than one-shot `TryOn`/`Undress` across a re-skin. `UndressSlot(slot)` strips one equipment slot in place (the removal half of a paper-doll per-slot toggle — `TryOn` re-adds; re-set `Outfit` so a re-skin honors it). `SlotTransmog(slot, appearanceID, opts?)` precisely sets **one** slot via the actor's `SetItemTransmogInfo` — the extras a bare `TryOn` can't reach: `opts.illusionID` (an enchant illusion, weapon slots — the shimmer has nothing to render on without a host weapon appearance), `opts.secondaryAppearanceID` (split shoulders / a Legion artifact's paired off-hand), and `opts.ignoreChildItems` (default true); `appearanceID` 0 renders the slot bare. Composes with `Outfit`/`TryOn` (the base look) by re-applying **last** for its slot, and — like `Outfit` — the per-slot overrides (`_slotMog`) are re-applied on the same `SetOnModelLoadedCallback` so an async re-skin doesn't wipe the illusion/appearance; `ClearSlotTransmog(slot)` forgets one. A scene actor skins arbitrary races correctly where a bare `DressUpModel` renders them white |

## Class

```
Frame (LibNUI)
  └─ Model   -- ui.Model
```

`Model` inherits `Frame` (`type = "ModelScene"`, `template = "ModelSceneMixinTemplate"`); options `rotateSpeed` (0.01 rad/px), `facing`, `minZoom`/`maxZoom` (2/16, camera zoom range), `spinFriction` (0.05, inertia decay), `spinTracking` (0.5, throw-speed follow). Full constructor-option and method reference in [README.md](README.md).

## Gotchas

- **Consumers MUST list `LibNUI-ModelViewer` in `## Dependencies`.** `Model` is bound at file-load time (`local Model = ui.Model`), so the widget must be registered before the consuming file runs. Missing the dependency ⇒ `ui.Model` is nil ⇒ `Model:new{}` errors.
- Registers onto the **shared** `LibNUI` global (via `X-NUI-UI: LibNUI` → `ns.ui`), not a private namespace, so `ui.Model` stays the canonical suite-wide access path — extraction is transparent to callers.
- A `ModelScene` actor skins arbitrary races correctly where a bare `DressUpModel` renders them white; a creature display only textures if it's a **baked** display (carries its own textures).
