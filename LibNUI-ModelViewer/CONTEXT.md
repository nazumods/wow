# LibNUI ModelViewer

**Deps:** LibNAddOn, LibNUI · **Global:** registers `ui.Model` (`LibNUI.Model`) on the shared LibNUI widget table · **Commands:** none · **DB:** none

Single-widget companion addon: the `ModelScene`-backed 3D model viewer, extracted from core LibNUI (issue #591) so only addons that present a 3D character / transmog viewer carry it. `Model.lua` is the setup file (`local ns = LibNAddOn(...)`); the addon declares `## X-NUI-UI: LibNUI` so `ns.ui` resolves to the shared LibNUI table, then registers `Model` back onto it. Consumers reach it as `ui.Model` / `LibNUI.Model` exactly as before, provided they add `LibNUI-ModelViewer` to their `## Dependencies` so the widget exists at file-load time.

## Files

| File | Purpose |
|---|---|
| `Model.lua` | Setup file (`LibNAddOn(...)`, binds `ns.ui` = LibNUI via `X-NUI-UI`) + the `Model` widget. `ModelScene`-backed 3D viewer (borrows dressup scene 596 for camera + a skinnable player actor); `DisplayInfo(id, useCustomizations?)`/`Unit(token, customRaceID?, useNativeForm?)`/`TryOn`/`Undress`/`UndressSlot`/`Dress`/`Outfit`/`SlotTransmog`/`ClearSlotTransmog`/`Aggressiveness`/`Scale`/`Spin`. `Unit`'s `useNativeForm` (default true) toggles the unit's native vs altered form (Worgen human, Dracthyr visage) — only effective when the unit itself has one. `DisplayInfo` defaults customizations **off** (a baked display carries its own textures; on only matches the player's own race). One player-sized actor renders every model, so races at natural size are inconsistent: `Aggressiveness(n)` (0 = natural, **default**; 1 = forced to ~human-male) drives Blizzard's bounding-box normalization (`SetNormalizedScaleAggressiveness` + `SetRequestedScale`, `effectiveScale = requestedScale * 1/maxBoundingBoxScale` via `UpdateScale`); `Scale(n)` is the user multiplier on top (= `requestedScale`). **Left-drag = actor yaw (rotate, with release inertia), right-drag = camera pan, wheel = camera zoom.** Yaw lives on the actor (so re-skins keep the framing); pan/zoom live on the borrowed scene's `OrbitCamera` (`GetActiveCamera()`): leftX mode set to `NOTHING`, rightX/rightY = `PAN_HORIZONTAL`/`PAN_VERTICAL`, wheel = `ZOOM`, and min/max zoom widened from the scene's tight 6–10 to `minZoom`/`maxZoom` (2/16) so the wheel has travel. Our `OnUpdate`/`OnMouse*` `SetScript`s replace the template's, so they forward to the mixin (`w:OnMouseDown/Up/Wheel`, `w:OnUpdate(elapsed)`) to keep the camera stepping (pan + zoom are eased by the `OrbitCamera`'s own `DeltaLerp` interpolation, default amount `.15`); only `LeftButton` arms the actor-yaw drag. **Rotation inertia:** since the yaw is on the actor (not routed through the eased camera), the drag tracks a throw speed (`_yawVel`, rad/sec, `DeltaLerp`-smoothed by `spinTracking` so placing the model precisely doesn't fling it) and, on release, keeps rotating and glides to a stop via the same engine `DeltaLerp` decay (`spinFriction`, ~1s) down to a `SPIN_CUTOFF` snap; a fresh grab zeroes the velocity. `Spin(v)` reads/sets the live velocity for a programmatic showcase spin (or `Spin(0)` to halt). `ResetView()` restores the load defaults — yaw back to `facing` (zeroing any spin), the captured `_naturalZoom` distance, and pan offsets (`_cam.panningXOffset/panningYOffset`) to 0; the user `Scale` multiplier is left untouched. The dragged yaw and remembered `Outfit` (a sourceID list, empty = undressed) are re-applied via a `SetOnModelLoadedCallback` after each async model load (which would otherwise reset the actor to its baked default), so the angle and worn transmog never snap back. Scale (`_applyScale`) is instead **re-asserted every frame** in `OnUpdate` — a cold first load resets the actor scale *after* the load-callback/backstop fire, so polling is the only reliable way to keep the size correction (idempotent, corrects within a frame). Use `Outfit` rather than one-shot `TryOn`/`Undress` across a re-skin. **`Outfit` diffs on set (#754)**: it undresses the slots the previous outfit occupied that the new one doesn't, so a shorter or different look swaps cleanly in place and an empty list undresses everything the last one held. The diff lives in the **setter**, not `_applyOutfit`, which stays purely additive (`TryOn` only — stripping there made every backstop re-apply flash the settled model bare, and it runs three times per load against an already-bare body). It works in **slots**, not sources: `GetSourceInfo` → `invType` → `C_Transmog.GetSlotForInventoryType` (which returns an *inventory* slot id, and 0 for the non-transmoggable ones — neck, finger, trinket, bag, ammo), memoized per source with **successes only**, so a source whose item data hasn't streamed yet self-heals instead of caching a permanent miss. That mapping is many-to-one — every weapon invType collapses onto a hand slot, a robe onto CHEST — so replacing a two-hander with a one-hander reads as "still occupied" rather than a drop. Slots carrying a `SlotTransmog` override are skipped, and an unresolvable source is skipped rather than guessed at (a missed strip is a leftover; a wrong one removes a piece the caller asked for). **`ForgetOutfit()`** clears the remembered list without touching the actor — what `Outfit({})` used to be borrowed for, now that an empty list means a real strip. The list is **shallow-copied** on set (`ns.lua.lists.map`), so a caller mutating its own list in place can't silently change what the next load re-applies. `UndressSlot(slot)` strips one equipment slot in place (the removal half of a paper-doll per-slot toggle — `TryOn` re-adds; re-set `Outfit` so a re-skin honors it). `SlotTransmog(slot, appearanceID, opts?)` precisely sets **one** slot via the actor's `SetItemTransmogInfo` — the extras a bare `TryOn` can't reach: `opts.illusionID` (an enchant illusion, weapon slots — the shimmer has nothing to render on without a host weapon appearance), `opts.secondaryAppearanceID` (**slot-dependent**: a genuine second appearance on the SHOULDERS for split shoulders, but a discriminator on the MAIN HAND — see the trap below), and `opts.ignoreChildItems` (default true). **`appearanceID` 0 does NOT bare the slot** — it is `NoTransmogID`, recording "no override for this slot" rather than "wear nothing there", so the actor keeps whatever it was last given and the piece goes on rendering; `ClearSlotTransmog(slot)` + `UndressSlot(slot)` is the way to empty one (measured in `Warbandeer_Collected`'s `DressingRoom:_bareSlot`, which moved off `SlotTransmog(slot, 0)` after a cleared shirt kept rendering). Composes with `Outfit`/`TryOn` (the base look) by re-applying **last** for its slot, and — like `Outfit` — the per-slot overrides (`_slotMog`) are re-applied on the same `SetOnModelLoadedCallback` so an async re-skin doesn't wipe the illusion/appearance; `ClearSlotTransmog(slot)` forgets one. **`_applySlotMog` writes the two WEAPON slots last, in a fixed order, behind `actor:ResetNextHandSlot()`** — ordinary slots are independent and go in `pairs` order, the hands are not: the actor keeps an internal "next hand slot" cursor deciding which hand a weapon lands in, and `SetItemTransmogInfo` makes its own dual-wield judgement on top of it, so left to drift the second weapon claims the hand the first is in and a two-weapon look renders as ONE weapon (the symptom that surfaced as a Titan's Grip pair rendering as its off-hand alone). Undress-both-then-reset-then-off-hand-then-main-hand is exactly what Blizzard's own two-weapon previews do (`Blizzard_PerksProgramModel.lua`, `Blizzard_CatalogShop_SharedUtil.lua`: "Since we are manually setting the 2 items in each hand, reset the actors sense of what hand to put stuff into"). **That is only half of it**: measured, the off-hand write then succeeds *and the actor holds the weapon*, and the following main-hand write clears the off-hand slot back to nil — `Blizzard_Transmog.lua`'s "offhand is processed first and mainhand might override offhand" — regardless of the main hand's `secondaryAppearanceID`. So the off hand is **read back and re-placed via `TryOn(id, "SECONDARYHANDSLOT", illusionID)`** when the actor disagrees with what was asked for; `handSlotName` is the only primitive that addresses a hand directly. Ordering alone cannot fix it (main-hand-first just moves the clobber onto the other weapon), and the repair is verified rather than assumed, so it never fires for the shield/holdable case that always worked, and it is **skipped entirely when the requested `appearanceID` is 0**: that is `NoTransmogID`, which records "no override" rather than an appearance to verify, so there is nothing for the read-back to disagree with and nothing `TryOn` could re-place — left unguarded it read the empty hand slot back as nil, called that a failed write, and fired `TryOn(0, "SECONDARYHANDSLOT", 0)` three times per re-skin to no effect. Net effect: a second WEAPON survives in the off hand, which it previously never did — the defect was invisible while the look builder's off-hand dropdown offered only shields and holdables. **The main hand's `secondaryAppearanceID` is a discriminator, not an appearance** — `-1` (`Constants.Transmog.MainHandTransmogIsIndividualWeapon`) = an ordinary weapon, `0` (`MainHandTransmogIsPairedWeapon`) = a Legion artifact whose off-hand is derived from it. Omitting it is not neutral: `ItemTransmogInfoMixin:Init` falls back to `NoTransmogID`, which is also `0` = PAIRED, so an ordinary main-hand weapon comes out flagged as half a pair. That is a **mislabelling** trap, *not* the cause of the off-hand clobber — that happens whatever the discriminator says, and the read-back repair covers it either way (the older docs claimed the discriminator caused it; it doesn't). A scene actor skins arbitrary races correctly where a bare `DressUpModel` renders them white |

## Class

```
Frame (LibNUI)
  └─ Model   -- ui.Model
```

`Model` inherits `Frame` (`type = "ModelScene"`, `template = "ModelSceneMixinTemplate"`); options `rotateSpeed` (0.01 rad/px), `facing`, `minZoom`/`maxZoom` (2/16, camera zoom range), `spinFriction` (0.05, inertia decay), `spinTracking` (0.5, throw-speed follow). Full constructor-option and method reference in [README.md](README.md).

## Gotchas

- **Consumers MUST list `LibNUI-ModelViewer` in `## Dependencies`.** `Model` is bound at file-load time (`local Model = ui.Model`), so the widget must be registered before the consuming file runs. Missing the dependency ⇒ `ui.Model` is nil ⇒ `Model:new{}` errors.
- Registers onto the **shared** `LibNUI` global (via `X-NUI-UI: LibNUI` → `ns.ui`), not a private namespace, so `ui.Model` stays the canonical suite-wide access path — extraction is transparent to callers.
- A `ModelScene` actor skins arbitrary races correctly where a bare `DressUpModel` renders them white; a creature display only textures if it's a **baked** display (carries its own textures).
- **The left-drag state is cleared on `OnHide`.** A hidden frame receives neither mouse events nor `OnUpdate`, so hiding the viewer mid-drag (ESC on a `special` window, a tab switch) means the release never reaches `OnMouseUp`: without the handler the drag stays armed holding a stale cursor X, and the next show snaps the yaw by the cursor's travel in between and then tracks it with no button held. `OnHide` also zeroes `_yawVel` so the viewer reopens at rest. It is the one `SetScript` here that doesn't forward to the mixin — `ModelSceneMixinTemplate` declares only `OnLoad`/`OnUpdate`/`OnMouse*`, no `OnHide`.
